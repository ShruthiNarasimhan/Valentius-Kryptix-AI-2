---

## 2. Experiment 1: Zero-shot vs Few-shot Prompting

### Objective

To compare the performance of zero-shot and few-shot prompting for customer sentiment classification.

### Methodology

A dataset containing 10 customer reviews was used. The model was asked to classify each review into one of three categories:

- Positive
- Negative
- Neutral

**Zero-shot prompting:** The model received the task instructions without any labeled examples.

**Few-shot prompting:** The model received three labeled examples before classifying the same 10 reviews.

### Results

| Technique | Correct Predictions | Accuracy |
|---|---:|---:|
| Zero-shot | 10/10 | 100% |
| Few-shot | 10/10 | 100% |

### Observations

- Both techniques correctly classified all 10 reviews.
- Zero-shot prompting performed well without examples.
- Few-shot prompting provided additional classification guidance.
- No accuracy improvement was observed with few-shot prompting on this dataset.

### Conclusion

Both techniques achieved identical accuracy. This experiment demonstrated that examples can guide model responses, although they do not necessarily improve accuracy for every task.

## 3. Experiment 2: Direct vs Step-by-Step Prompting

### Objective

To compare direct prompting and step-by-step prompting when solving a multi-step mathematical problem.

### Problem

A shopkeeper purchases 40 notebooks at ₹25 each. He sells 30 notebooks at ₹35 each and the remaining 10 notebooks at ₹20 each.

Calculate:

- Total Cost Price
- Selling Price of the first 30 notebooks
- Selling Price of the remaining 10 notebooks
- Total Selling Price
- Profit or Loss
- Profit or Loss Percentage

### Expected Calculation

**Total Cost Price:**

40 × ₹25 = ₹1,000

**Selling Price of first 30 notebooks:**

30 × ₹35 = ₹1,050

**Selling Price of remaining 10 notebooks:**

10 × ₹20 = ₹200

**Total Selling Price:**

₹1,050 + ₹200 = ₹1,250

**Profit:**

₹1,250 − ₹1,000 = ₹250

**Profit Percentage:**

(250 / 1000) × 100 = 25%

### Results

| Evaluation | Direct Prompting | Step-by-Step Prompting |
|---|---|---|
| Correct calculation | Yes | Yes |
| Correct final answer | Yes | Yes |
| Mathematical accuracy | 100% | 100% |
| Response organization | Detailed | Explicitly structured |

### Observations

- Both prompting techniques produced the correct final answer.
- The direct prompt also generated calculation steps.
- The step-by-step prompt explicitly requested an organized explanation.
- No difference in mathematical accuracy was observed.

### Conclusion

Both techniques successfully solved the problem. Step-by-step instructions helped make the expected response structure more explicit.

## 4. Experiment 3: Structured JSON Output

### Objective

To evaluate the model's ability to extract invoice information from unstructured text and return valid JSON according to a predefined schema.

### Methodology

Five invoice descriptions were provided to the model.

The required JSON fields were:

- `invoice_number`
- `customer_name`
- `invoice_date`
- `amount`

The experiment initially used a schema with non-nullable fields. It was then improved by allowing nullable values for missing information.

### Initial Schema Results

| Test Case | Result |
|---|---|
| T1 | Successful after date-format correction |
| T2 | Successful |
| T3 | Successful |
| T4 | Failed: Missing amount returned as 0 |
| T5 | Failed: Missing date returned as an empty string |

**Initial success rate:**

3/5 × 100 = 60%

### Improved Schema

The schema was updated to allow nullable values.

For example:

- Missing invoice amount could be represented as `null`.
- Missing invoice date could be represented as `null`.

The prompt also specified the required date format as `YYYY-MM-DD`.

### Improved Results

| Test Case | Result |
|---|---|
| T1 | Successful |
| T2 | Successful |
| T3 | Successful |
| T4 | Successful: Missing amount returned as null |
| T5 | Successful: Missing date returned as null |

**Improved success rate:**

5/5 × 100 = 100%

### Observations

- The initial schema did not handle missing information correctly.
- Nullable fields improved missing-value handling.
- Explicit date-format instructions improved date consistency.
- Structured outputs helped maintain a consistent JSON format.

### Conclusion

The improved schema achieved a 100% success rate on the five test cases. This experiment demonstrated the importance of schema design and clear instructions when generating structured LLM outputs.
